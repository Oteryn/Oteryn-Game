# World pins

`<slug>.json` pins one reviewed World bundle (`OTERYN_WORLD_PIN/v1`):

| field | meaning |
| --- | --- |
| `digest` | the `OTERYN_WORLD_BUNDLE/v4` digest of the bundle the compiler builds from this tree |
| `project_format_version`, `world_schema_version`, `content_revision` | must equal the identity derived from `project.json` and `manifest.json` |
| `production` | `false`; a production pin on a non-production build fails the gate |
| `entry_start` | `{x, y, floor}`: a walkable, non-blocking base cell inside the World bounds whose top-level entries hold no wall and no plain Item, an Item entry without a Terrain record (the node blocks a plain Item whose served definition does not state it walkable, and then refuses boot with `BOOT_WORLD_BUNDLE_REFUSED`) |
| `inputs_digest` | SHA-256 over the git blob ids of the compiler inputs (pin files `<slug>.json` excluded), so it is equal on a branch and on its squash-merged tree; the root `Cargo.toml` and `Cargo.lock` count only in their World-scoped form (the dependency closure of the World crates, without workspace members or unrelated workspace dependencies; ARCH-WORLD-CONTENT-SERVE-1 §1.2, PIN-SCOPE-1) |

`<slug>.identity.json` is generated by `world-bundle-compiler derive-identity <root> <slug>`
and is never hand-edited; `<slug>.ruleset.json` is the only hand-written identity source.
`world-bundle-compiler pin-check <root> <out>` (the `world_bundle` job of `game-gate`) checks every
pin, builds the bundle twice and writes `<slug>-<digest>.otwb` and `artifact-name.txt`.
A stale or merge-conflicted pin is never edited by hand: stage the inputs, then run
`cargo run --locked --release -p oteryn-world-bundle-compiler -- pin-refresh .`, which rewrites
every pin's digests and revisions, its identity file and the preproduction manifest's
`[world_bundle]` table, keeping the reviewed `entry_start`. `python3
tools/content-migration/regenerate_content.py --resolve` runs it on a merge that conflicted in a
pin. `pin-check` stays the gate.
