## Owning implementation handoff

The architect reconciles IMBUE-FORGE-0 and the static Item representation for
Basic tier 1 required by 12 profiles. Candidate-proposal discrepancies include
fees 5000/30000/200000 versus sourced 7500/60000/250000, Basic inscription versus
sourced Intricate/Powerful inscription, Stash availability, Strike additive
modifiers and Vibrancy repeated-paralysis semantics. These need explicit
disposition rather than weakening the selected evidence.

The coordinator owns allocations, leases, independent review and protected
integration. IMBUE-CONTENT-1 handles canonical content and Quest predicates;
the Item owner handles tier 1 lowering and proposed identities; IMBUE-1 handles
durable instance state and transactions; IMBUE-RT-1 handles timers/effects;
IMBUE-SCROLL-1 handles scrolls/Etcher; IMBUE-WIRE-1 and the client owner handle
transport/UI. Existing combat/formula owners retain effect-order ownership.

The pinned audit in `audit-report.md` identifies unpopulated canonical indices,
UNKNOWN Item type/tier lists and absent execution paths. Passing authoring
checks does not complete those implementation children or their restart,
transaction-failure, transfer, combat and client integration tests.
