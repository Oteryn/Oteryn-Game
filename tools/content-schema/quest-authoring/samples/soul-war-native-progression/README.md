# Soul War first-cycle native progression qualification

This is a **non-admitted qualification input**, not a second Quest engine, a shipping
Quest catalogue, a live binding, or a complete Soul War implementation.

`quest-state.json` is generated by `soul_war_native_progression.py`. It uses the
existing native `OTERYN_QUEST_STATE_LOWERING/v1` loader, `QuestStateCatalogue`
comparisons and effects. `native_soul_war_progression.rs` path-loads the unchanged
`apps/game-server/src/quest/mod.rs`; no native source is copied or patched.

## Bounded result

Ten tracks: started, five independent miniboss flags, taint rank, first-taint time,
final access and Megalomania victory. Twenty-nine transitions cover first start,
each distinct boss at each possible taint rank, the all-five gate and victory.
The final reward/completion transition remains `COMPUTED`/`NOT_SUPPORTED`.

Each boss credit requires its own flag to be zero; a duplicate cannot advance the
taint rank. The first successful credit uses the existing `SET_NOW` effect; later
credits do not overwrite that timestamp. The final-access transition checks all
five flags plus start and taint rank in the same eight-effect transaction shape,
within the existing native limit. No completed quest, XP, outfit or Item is granted.

The qualification exercises all 120 miniboss orders, repeated kills, every missing
flag, stale rank, replay, first-taint timestamp preservation, test-copy serialization
and fail-closed partial guards. The test applies native reducer results to a test
map only; this is **not PostgreSQL restart/concurrency, session fencing, party credit,
NPC dialogue, world-entry or gameplay proof**.

## Reproduce from the repository root

```sh
python tools/content-schema/quest-authoring/soul_war_native_progression.py --check
python -m unittest discover -s tools/content-schema/quest-authoring -p test_soul_war_native_progression.py
python tools/content-schema/quest-authoring/qualify_soul_war_native_progression.py
```

The last command needs the repository-pinned Rust toolchain and cached dependencies.
It creates a temporary isolated Cargo package, pins its three direct dependencies to
workspace versions, rejects resolved packages absent from the repository lock,
and runs the real native module's tests with `--frozen`. It changes no workspace
membership, production files, native registry, server configuration or database.
The optional `--report /path/outside/repo/result.json` retains source hashes/results.
The Python discovery check covers generated-byte and scope invariants; the explicit
native command is a separate qualification and is not silently claimed as a CI run.

## Source and remaining ownership

The reconstruction packet is pinned in `authoring_sources`. Crystal summer-update
`00ce02a57ca5a12e48f32a3476e37471167e4c3f`,
`data-global/scripts/quests/soul_war/soul_war_mechanics.lua:93-118`, records one flag
per distinct boss, first-taint time and the next taint. The canonical Oteryn identity
is reused, but qualification track names are **not** admitted canonical track IDs.

This resolves the narrow question of native scalar expressibility; it does not
close the runtime hold on the earlier aggregate count-five projection. Full caller
eligibility/credit, taint effects/expiry/reset, repeat cycles, boss cooldowns, world
interactions, Megalomania outcome, Revenant Outfit and random-one-of-18 delivery remain
unbound. Every such hold is retained in the fixture. Do not register/embed this sample.
