# NPC trade quest continuations

`content/quests/shared-trade-callbacks.json` admits bounded storage-only continuations through the existing NPC trade and Quest owners. A rule names its canonical NPC, buy/sell side, up to eight distinct canonical Item keys, exact positive unit price and offer count, minimum actual Item units, and up to eight persisted storage predicates/effects. Missing persisted milestones are ineligible. Rules may not overlap their NPC/side/Item selectors. Sources cite the pinned donor and any explicitly documented conservative repair.

The trade owner resolves the rule before its transaction, binds all terms into its request, then independently checks persisted milestone values under the current Character root lock. An eligible successful trade captures those values and its immutable trade identity in the existing pending Quest obligation relation, in the same physical transaction as the item/coin changes and audit. An eligible obligation that cannot fit refuses the whole trade. An ineligible trade can still commit its ordinary exchange and produces no quest obligation; replay cannot create one later.

Migration 1109 keeps reward-claim semantics and adds a typed `npc_trade` source. Its deferred source guard proves the exact original transaction, Character and command, and verifies captured values against the persisted tracks at capture. Source identity, rule binding and captured state are immutable. New and replaced trigger functions retain the owning schema-bound search path; existing runtime grants still allow updates only to obligation state, result code and update time. The separate `trade_obligation` cause can only execute a configured trade transition; the Quest writer checks the original NPC, side, item, price, units, offer count, World, rule binding and captured eligibility before evaluating current progress through its normal fenced writer. Only that writer consumes the obligation with its once-only receipt. This adds no client wire command or second quest-state writer.

Normal trade and exact receipt replay refresh Quest admission, which also drains pending work on cold admission and retry cadence. Captured evidence is a past fact, never current authority: the Quest mutation still resolves the current session, lease, World scope and ownership fence. Pending work remains durable after a lost acknowledgement or ended NPC conversation. Existing reward-claim obligations keep their source and checks unchanged.
