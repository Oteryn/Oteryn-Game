## Ownership and bounded result

Extends `world_event::record_reset` inside the existing `WorldReset` finalization transaction. No replacement DAILY reward, raid scheduler, server-save job or Channel spawn owner is introduced. `world_event::changes` persists one immutable daily decision per `(WorldId, reset_epoch)`. Each Channel reads it before the existing daily map projection, fungus/Grimvale spawn substitutions, trader map/NPC placement and Thawing Item placement. Physical occurrences remain Channel scoped; decisions and contributions are World scoped.

The authored catalogue is `content/encounters/world-changes/owner-catalogue.json`. Only its four READY candidates feed selection; the existing donor percentages, independent purpose draws and uniform trader-town choice are retained. World and reset epoch seed the existing simulation-determinism draw. Calendar facts come from the committed reset activation timestamp, never Channel boot time. The June seasonal window is inclusive June 1/exclusive July 1. A reusable annual window rule also handles year wrapping; dates for held seasonal titles are not invented.

Migration `1100_world_change_owner.sql` adds decisions, epoch-scoped coal/medicine/vote tallies and immutable operation receipts. Reset changes the namespace, so current tallies become zero while history remains queryable. Contributions serialize through the same admission relation fence used by reset finalization; arithmetic is checked and retries return their original tally. Installation activates nothing. Existing committed epochs are backfilled on first read from their immutable activation timestamps; new epochs are recorded in the reset commit. Once stored, decisions are loaded unchanged. A retiring or stale nonzero epoch refuses boot.

Number allocation: refreshed `origin/main` at `ed788c4bb1`; main highest migration 990, open-PR highest 998, so 1100 was free in the requested 1100–1104 range. The same main/open-PR allocation was rechecked immediately before publication; 1100 remained free.

READY below means the shared active-state gate and existing daily physical path are available. It does not claim full quest, reward, achievement or client qualification. HELD entries return false from the active gate even if an unrelated authored personal recipe exists. Contribution bookkeeping does not by itself qualify Steamship, Swamp Fever or Rathleton.

General W1 bundle activation (ADR-0021 §4.7 / EVENTS-WORLD-1 W2/W4) remains unqualified: `compile_selection_source` still explicitly refuses missing native bindings. The planned `game_world_change_activations` table and `world_change_activation` evaluator have no implementation on this main. This slice preserves the existing daily RNG purpose and physical seams; it does not claim to complete the generalized W1 compiler or admit its held layers. D1055 supplies Nomads' equal camp weights (1 each); its held status concerns the activation trigger and native camp realization, rather than an unresolved choice of relative weights.

## CALLBACKS FOR QUEST LANES

- Observe for display or boot: `DurabilityRoot::world_changes(world, expected_epoch)` returns the current immutable `DailyWorldChanges`, or `None` for an uninitialized/stale/retiring World. Observation is not authority to mutate a Character. `owner::is_active(&day, key)` recognizes `thawing`, `their_masters_voice`, `oriental_trader`, `grimvale`; unknown and HELD keys return false.
- Require an active change before a quest write: use `world_event::changes::load(&mut tx, world, expected_epoch)` inside the quest owner’s existing fenced semantic transaction, then require `owner::is_active(&day, key)`. Keep this check and the quest mutation in that same transaction; do not authorize from an earlier `world_changes` snapshot. The load acquires the existing admission fence, which also excludes reset publication. Follow the existing recovery → admission → Character/session lock order.
- Contribute: `changes::contribute(&mut tx, &recovery, world, epoch, operation_id, ContributionKind::{Coal,Medicine,Votes}, amount)`. The quest lane must validate its live Character/session/generation, eligibility and custody, then debit the resource in this **same transaction**. Use a stable server-owned operation id; replay returns `Replayed(original_tally)` and must not debit again. A conflicting resource/amount, zero amount/id, stale epoch or checked overflow returns `Rejected`. Applied/Replayed are pending until the caller commits; rollback removes both tally and receipt.
- Observe contributions: `changes::tally(&mut tx, world, epoch, kind)` returns the exact epoch tally, absent = zero. Historical queries are explicit; a new epoch uses fresh zero tallies. No separate reset-tally command exists.
- Held contribution titles have no accepted activation threshold/ballot-to-effect binding here. Do not expose a player donation/voting command or grant transport, rank, rewards, spawns or portals based on the generic bookkeeping API. Rathleton still needs a ballot identity, voting period, spent-point debit and rank owner. Coal and medicine still need qualified native item/custody and title-specific transition rules.
- Spawns, portals and layers must pass their existing map/overlay/content admission seams. The four READY entries reuse current physical activation. The generic owner cannot install arbitrary geometry or turn a storage namespace, NPC presence, boss spell or extracted layer into a qualified title.
