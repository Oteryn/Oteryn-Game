Tekst mieści się w 200 bajtach UTF-8, nie wymaga interpretacji markup i dosłownie zgadza się ze wszystkimi obecnymi opisami przypiętych XML. 46 tekstów zgadza się w obu Crystal i Canary, 68 w obu Crystal przy braku takiego opisu Canary.

To są własne teksty `flavortext`, które Template:Infobox Object przekazuje do Item/Look. Notes, poradniki i teksty questów nie są podstawą opisów. XML pozostaje potwierdzeniem tekstu; zgodność silników sama nie nadaje autorytetu gry.

Istniejący `ReferenceItemSemantics.presentation.description: ReferenceItemField<String>` i kodek już obsługują opis, z limitem 200 bajtów. Formalne źródłowe właściwości to `/item/presentation/flavor_text` i `/item/presentation/inspection_description`. Dla tych 114 identyczne teksty zamykają oba znaczenia. Nie jest potrzebne nowe pole ani zmiana ABI. Każda grupa classification tych 114 jest obecnie UNKNOWN: opis nie zamyka klasyfikacji, przypisania rodzin, admission ani materializacji.

**1515 innych ID** przechodzi pozostałe kontrole, lecz własny Wiki tekst ma końcową kropkę nieobecną w każdym XML. Crystal wypisuje XML description bez zmiany tekstu. Nie usunięto ani nie dopisano kropki; te ID pozostają poza ścisłą paczką i wymagają jawnej decyzji o autorytecie literalnego tekstu Wiki. Kolejne 924 ID ma inne różnice lub brak potwierdzającego opisu XML. To razem 2439 propozycji do decyzji źródłowej, nie gotowe dane Native. Pozostałe blokady i pełna lista 3694 ID są w raporcie JSON; liczby blokad nakładają się i nie należy ich sumować.

Źródła odczytano z zachowanych publicznych przechwyceń Chrome/CDP, wykonanych po blokadzie zwykłego HTTP, oraz lokalnych plików przypiętych GitHub XML. W tym etapie nie wykonano nowych zapytań internetowych, nie użyto RDC i nie zmieniono projektu. Dla rawbox przechwycenie zawiera deklarowany SHA całego artykułu, a nie pełne bajty artykułu; pełny rawbox i jego rzeczywisty SHA są zachowane. Parser miał 8 znaczących testów parametrów/komentarzy/duplikatów/gnieżdżenia. Pakiet jest propozycją źródłową, nie został zastosowany.

Minimalna przyszła implementacja: osobny compiler i cienki native wrapper zamkniętej paczki 114, wykorzystujący istniejące strażniki nazw/ID/membership/world i atomowe prevalidation; tylko UNKNOWN→Known lub identyczna wartość idempotentna. Wymagane negatywne testy: inna Known nazwa/opis, przeciwny lub pusty raw flavor, wspólne ID, brak binding/membership, zmieniony rawbox/koordynaty, source po cutoff, markup, 201 bajtów i zachowanie wszystkich innych Native pól. Wspólny source catalog i engine importer pozostają byte-identyczne; ewentualny writer używa dedykowanego helpera istniejącej formalnej właściwości.
