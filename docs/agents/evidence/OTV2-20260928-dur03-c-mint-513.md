A deferred constraint trigger requires that every ItemInstance commit with its Ground row, receipt and
outbox event from the same transaction, in the death's own channel and generation. The instance,
location and receipt rows are immutable, and all four relations reject TRUNCATE. The outbox has no
DELETE path. PUBLIC is revoked. The runtime role gets SELECT and INSERT, and the control role gets SELECT.

## Writer (`item_mint.rs`)

- `freeze_item_mint` checks every registered bound before allocation. It then fixes the TransactionId,
  EventId and ItemInstanceId (producer-owned UUIDv7), the trusted `statement_timestamp` and the exact
  event bytes. It mutates nothing.
- `commit_item_mint` runs: recovery fence → admission-relation locks → cause advisory lock → receipt by
  full cause. If a receipt exists, it returns the stored result, or `ConflictingCause` when the intent
  differs. Otherwise it checks the identity-reuse guard (`ConflictingCandidate`), then the runtime-scope
  assignment `FOR SHARE` on the death's World/Channel/generation held by this node,
  `prove_current_incarnation`, and 4 inserts.
- `reconcile_item_mint` runs: recovery fence → cause lock (it waits for any in-flight attempt) → receipt.
  `None` proves nothing committed.
- The typed cause has a `#[cfg(test)]` constructor only. The candidate is not `Clone`.

## RL-08 measurement (D51 re-decision input)

Thirty samples per pass on local PostgreSQL 17.11, unloaded, from two runs:

| Pass | Statements (excluding BEGIN/COMMIT) | Median | p90 | Max |
|---|---|---|---|---|
| freeze (not RL-08 work) | 2 | 2.0-2.3 ms | 2.8-3.1 ms | 5.2 ms |
| commit, new cause | 28 (incl. 17 `LOCK TABLE`) | 11.2-14.3 ms | 14.8-19.2 ms | 40.0 ms |
| commit, replay | 21 | 6.9-7.7 ms | 10.4-13.2 ms | 24.4 ms |
| reconcile, committed | 4 | 3.6-3.8 ms | 5.9-7.3 ms | 7.3 ms |
| reconcile, not committed | 4 | 3.0-3.6 ms | 4.9-6.0 ms | 7.3 ms |

- Every pass is far below `DFR-DB-PASS-MS` (2,000 ms). Three units took at most about 60 ms in wall time.
- A reconcile after an unknown outcome waits on the cause lock only while the earlier attempt's server
  transaction is alive. That is bounded by its `transaction_timeout`, about one pass. On PostgreSQL 17,
  no separate statement timer is armed while `statement_timeout` equals `transaction_timeout`.
- Structural finding: 3 units cover exactly one ambiguity cycle (attempt, reconcile, retry). A second
  transient failure leaves the candidate held. Under D52 it is then terminally not minted once its
  generation ends. No duplicate is possible at any value, because the full-cause PK is the authority.
- RL-08's registered value is unchanged. The re-decision belongs to the owner.
