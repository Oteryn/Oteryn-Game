A deferred constraint trigger requires that every ItemInstance commit with its Ground row, receipt and
outbox event from the same transaction, in the death's own channel and generation, and that the
receipt equal its cause's reservation (full cause, intent binding, TransactionId, EventId,
ItemInstanceId, `occurred_at`, `sha256(envelope)`). The instance, location and receipt rows are
immutable. A reservation changes only by one `work_units_used + 1` charge with every other column
unchanged; it has no expiry or DELETE path. All five relations reject TRUNCATE. The outbox has no
DELETE path. PUBLIC is revoked. The runtime role gets SELECT and INSERT, plus UPDATE on
`work_units_used` only; the control role gets SELECT.

## Writer (`item_mint.rs`)

- `freeze_item_mint(authority, node, request)` checks every registered bound first. Then, in one committed
  transaction: recovery fence → cause advisory lock → reservation by full cause.
  - Existing row: a different intent is `ConflictingCause`. With a receipt (terminal) it resumes as is.
    Otherwise its fence must name `node` and be live (assignment `FOR SHARE` on the death's
    World/Channel/generation held by `node` + `prove_current_incarnation`), else `AuthorityRejected`.
    Resuming returns the same IDs, event bytes and `work_units_used`.
  - No row: the same live-fence check, then producer-owned UUIDv7 IDs, the trusted
    `statement_timestamp`, the exact event bytes, and an INSERT with `work_units_used = 0`.
- Every `commit_item_mint` and `reconcile_item_mint` first runs a separate committed charge pass:
  recovery fence → `UPDATE … SET work_units_used = work_units_used + 1 WHERE <full cause> AND
  transaction_id = … AND work_units_used < 3 RETURNING`. The row lock plus re-evaluated predicate
  makes it race-safe. No row means `CapacityExceeded`, and the pass's work is not run.
- `commit_item_mint` then runs: recovery fence → admission-relation locks → cause lock → receipt.
  With a receipt it returns the stored result or `ConflictingCause`. Otherwise it checks that the
  reservation matches the candidate, runs the identity-reuse guard, requires the reservation's fence to
  name `node` and be live (D52), and does 4 inserts.
- `reconcile_item_mint` then runs: recovery fence → cause lock (it waits for any in-flight attempt) →
  receipt. `None` proves nothing committed.
- The typed cause has a `#[cfg(test)]` constructor only. The candidate is not `Clone`. Its
  `work_units_used` is the last reservation value this holder observed.

## RL-08 measurement (D51 re-decision input), re-measured in repair round 1

Thirty samples per call on local PostgreSQL 17.11 (`--test-threads=1`, unloaded). Each commit and
reconcile call is now two passes: the committed RL-08 charge (3 statements), then the call's own work.
The pre-repair single-pass figures are superseded.

| Call | Statements (excluding BEGIN/COMMIT) | Median | p90 | Max |
|---|---|---|---|---|
| freeze, new reservation (not RL-08 work) | 8 | 5.1 ms | 7.9 ms | 17.5 ms |
| freeze, resume (not RL-08 work) | 7 (5 when terminal) | 3.3 ms | 4.5 ms | 6.6 ms |
| commit, new cause | 3 + 29 (incl. 17 `LOCK TABLE`) | 11.3 ms | 22.5 ms | 27.4 ms |
| commit, replay | 3 + 21 | 8.2 ms | 11.8 ms | 12.9 ms |
| reconcile, committed | 3 + 4 | 4.9 ms | 6.6 ms | 8.7 ms |
| reconcile, not committed | 3 + 4 | 4.4 ms | 6.3 ms | 11.8 ms |

- Every pass is far below `DFR-DB-PASS-MS` (2,000 ms). Three units take at most about 85 ms in wall time.
- The charge is durable per logical transaction, and a re-freeze or restart never resets it. The
  structural finding below therefore now holds per cause, not per process-local candidate.
- A reconcile after an unknown outcome waits on the cause lock only while the earlier attempt's server
  transaction is alive. That is bounded by its `transaction_timeout`, about one pass. On PostgreSQL 17,
  no separate statement timer is armed while `statement_timeout` equals `transaction_timeout`.
- Structural finding: 3 units cover exactly one ambiguity cycle (attempt, reconcile, retry). A second
  transient failure leaves the cause held, with its reservation and TransactionId unchanged. Under D52
  it is then terminally not minted once its generation ends. No duplicate is possible at any value, because the full-cause PK is the authority.
- RL-08's registered value is unchanged. The re-decision belongs to the owner.
