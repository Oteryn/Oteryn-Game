## PROVEN: production owner route

Native think retains the authored source list and emits `ProfileAbilityProposal`. `gameplay_transport/monster_profile_cycle/physical_spell.rs` admits Attack proposals against the runtime's exact current creature identity, role and loaded source closure. It joins current Map/Item facts, target/session state, visibility, protections and equipped element policy before executing the existing spell owner. Composed attacks use the same prepared geometry plus the current creature role, health and policy owners. Item attacks use the existing source Item transaction separately; they do not turn field creation into a damage callback.

`DamageSpellOwner::execute_current` independently validates the runtime owner work stamp and delegates to the existing preparation/commit implementation. Its current condition, composite damage and invisibility operations reach the real `ChannelSpellStates` implementation. They do not clone an authority fence or fall back to permissive default condition handlers. Existing player HP/MP, lethal receipts, equipment, condition suppression and replay owners remain responsible for their mutations.

Windup and chain drains receive the caller-issued work stamp. Read-only pending-source metadata identifies each exact source, target, target session and, for chains, frozen hop origin. The asynchronous adapter prepares a separate current reader for each pulse and validates the actual Map/Item transaction after the last awaited read. An aborted or invalid transaction preserves pending pulses; the chain adapter restores any temporarily taken owners before returning. Only after that validation can the existing timer owner remove a pending entry and create its non-cloneable due pulse. A missing per-pulse reader or current sight fact in an otherwise valid transaction becomes a retained refusal; it does not turn into a retryable second application.

## PROVEN: movement observation stays in the position owner

Crystal queues an interval-zero attack when a relevant creature moves, rather than when it merely turns: `src/creatures/creature.cpp:488–495`, `src/game/game.cpp:6996–7000`. Coordinator ANSWER A (`6543529998`) authorizes a minimal derived fact in Oteryn's existing position owner.

`VersionedPosition` now has a private `last_translation_revision: u64`; `MovementPositionSnapshot::last_translation_revision()` is read-only. Admission initializes zero. Actual coordinate or floor changes copy the already-generated position revision into that field. Pure turns and same-cell compare-commits keep the prior marker. Cardinal movement, the NPC-specific path, common same-slot relocation and staged spell relocation all update it. No second clock, counter, store, ledger or movement callback dispatcher is added.

An out-and-back translation therefore remains distinguishable even when the current coordinates equal the prior coordinates. The consumer also compares the exact actor incarnation and context; a recycled slot's zero marker cannot impersonate an older actor's history. The field participates in exact snapshot equality. Manual `Debug` preserves the preexisting byte representation used in spell/relocation bindings, whose existing position revision already changes on each write.

The real owner tests are `translation_stamp_ignores_turns_and_same_cell_writes`, `translation_stamp_observes_out_and_back_and_rejects_stale_snapshots`, `translation_stamp_tracks_relocation_in_the_same_position_owner`, and `translation_stamp_is_scoped_to_the_exact_actor_and_current_owner`, in `entities/src/carrier/channel_actor_position_tests.rs`. Existing NPC movement and staged spell relocation tests also assert the derived marker and replay behavior. Historical accepted layout stays frozen at 168 bytes in its separate test type; the actual Slot measures 184 bytes inside the preexisting D314 184-byte ceiling. No capacity increase is made.

### Approved difference: magnitude distribution

[Q7, comment `6544184071`](https://github.com/Oteryn/Oteryn-Game/pull/2766#issuecomment-6544184071), is resolved by [ANSWER A, comment `6544219482`](https://github.com/Oteryn/Oteryn-Game/pull/2766#issuecomment-6544219482): retain the existing deterministic uniform damage policy without changing shared randomness. This accepts an explicit difference in magnitude distribution; it does not claim equivalence to Crystal's truncated-normal law. The approved position-owner translation marker remains a separate implementation authorization, not an eighth scope exclusion.

Crystal's [normal_random, tools.cpp:442–450](https://github.com/zimbadev/crystalserver/blob/201189f871d23597b82caf88fd611454a2ddefb8/src/utils/tools.cpp#L442-L450), samples a normal distribution with mean 0.5 and standard deviation 0.25, rejects values outside [0, 1], scales onto the ordered bounds, and rounds with `std::lround`. Equal endpoints produce the same fixed magnitude, but matching variable endpoints does not match the probabilities between them.

Oteryn's existing [uniform_draw, lines 3–14](https://github.com/Oteryn/Oteryn-Game/blob/a29cedbe74c0f1cb1f87334e5102907d9de97d4e/crates/gameplay/domain/src/domain/uniform_draw.rs#L3-L14), instead maps a deterministic decision to `minimum + decision % span`. This is the repository's **uniform magnitude projection**, with the finite-domain modulo bias when the span does not divide 2^64; it is not truncated-normal sampling. The mismatch predates this PR: the baseline [DamageSpellOwner magnitude draw](https://github.com/Oteryn/Oteryn-Game/blob/a52549e3b9230c7486a24df66f4e8ec59d1f96cb/crates/gameplay/spell/src/creature_damage_spell/mod.rs#L1991-L2005) already used that helper, and the baseline [composed owner qualification](https://github.com/Oteryn/Oteryn-Game/blob/a52549e3b9230c7486a24df66f4e8ec59d1f96cb/crates/gameplay/spell/src/creature_damage_spell/composed.rs#L588) explicitly retained `PROJECT_UNIFORM_DRAW` and `GLOBAL_UNVERIFIED`. This PR makes those existing owners reachable for more admitted sources; it does not turn their earlier projection into donor-distribution parity.

The owner-decided [spell schema S5](https://github.com/Oteryn/Oteryn-Game/blob/a29cedbe74c0f1cb1f87334e5102907d9de97d4e/docs/architecture/OTERYN_SPELL_AUTHORING_SCHEMA_V1.md#L380) places sampling in the world combat rule, separately from formula bounds; it does not select uniform sampling or approve equivalence to Crystal. [ATTACK-DIST-0, lines 29–45](https://github.com/Oteryn/Oteryn-Game/blob/a29cedbe74c0f1cb1f87334e5102907d9de97d4e/docs/architecture/reviews/OTERYN_GAME_ATTACK_DIST0_AUTO_ATTACK_DRAW_DECISION_2026-10-13.md#L29-L45), retains a working default for player auto-attacks and explicitly leaves creature melee undecided. ### Current-owner refusals and bounds within admitted attacks

These are concrete applicability limits of the current owners, not additional coordinator-approved scope exclusions or claims that an unsupported branch has executed successfully.

- **Composed creature secondary effects:** a player-owned creature that requires atomic primary damage plus attached conditions, or damage-derived healing, is refused before primary writes when the existing composed owner cannot represent that joint receipt. Current ordinary players continue through their real composite condition owner. No branch is silently discarded and no negative damage is invented as healing.
- **Top-creature callbacks:** Crystal uses the tile's arrival order (`src/items/tile.cpp:251–257`, insertion at `1046–1049` and `1671–1674`). A sole current occupant proves the top recipient. Multiple current occupants have no available arrival-order owner proof and refuse that callback; actor ID, slot order and placement order are not substitutes.
- **Chain trace geometry:** the existing bounded Movement search supplies cardinal presentation traces. It is not claimed to reproduce Crystal's diagonal chain FX path. Its actual search now distinguishes known blockers/void cells from unavailable current Item/Map facts, charges real work, and refuses unknown visited facts before admitting a trace or timer. A completed known search with no route remains an empty trace. This qualification is separate from the unallocated network presentation boundary.
- **Bounds:** existing cast/recipient/timer/replay limits remain in force. The 64-recipient constraint applies after the actual cast area is selected; unrelated distant actors no longer make an otherwise valid composed or appearance cast fail. Bounded current authority does not mean an arbitrary world-sized unbounded cast.
- **Element coverage:** qualified direct primaries permit exactly physical, fire, earth, energy, ice, holy, death, drowning, life drain and mana drain. The dispatch reader includes `ReferenceResistanceKind::Drown`; raw composed `untyped` callbacks remain with their separate raw-health owner.
