## Invariants, failures and retries

- Greeting matching uses consecutive whole words and nearest in-range same-floor candidates. Native talk opens only supported generated/literal or explicitly bound quest/service conversations; greeting admission cannot execute stateful script branches or award a reward. Exact closed NPC sets retain source messages while preserving existing travel/Premium services. A separate display-name projection covers NPCs with held dialogue. Conditional quest greetings distinguish an unreadable cache from an absent/negative track.
- Bank grammar admits only the bounded explicit commands and positive digit-only amounts. Deposit-all becomes an exact amount before prompt retention. One non-Clone confirmation is consumed by any response and requires the same session, Character, World, NPC identity/generation, conversation revision and monotonic unexpired clock. Actual dispatch additionally binds catalogue, item/session fence and node incarnation, reads current bank conversation, validates caps through the wrapper, and retains the exact confirming command in the queued durable request. Preview is followed by another current-conversation check; unknown enqueue/resume/storage outcomes remain unknown rather than being converted to a BankResult refusal.
- Trade offers are projected through the pinned exact Item reference and bounded wire price/count, preserving source subtype separately. Actual trade_in requires live exact NPC, engagement/range, open window, bounded quantity and current catalogue revision; it selects from the same shown projection, compares price/side and ensures the source row is still an offer of that NPC. Unsupported alternate-currency rows are refused by this ordinary path. Full durable trade integration was previously traced in economy; this report does not claim all dispatch complete.
- Walking profiles require the exact admitted catalogue/model and source speed/floor-mode fields. A proposal retains one shuffled order and has at most four candidates; coordinate arithmetic, placement radius and current occupancy are checked. Terrain checks full server/client/frame/map pins, walkability, same PZ class, no floor change/teleport and known no-height data. Actual commit reads current item barriers/fields beneath the existing scope transaction, rechecks that scope and position after awaits, uses a runtime try-lock, tests static triggers again, holds the conversation lock for the final no-customer check and commits through Movement.
- Voice profiles use exact source presence fields, bounded parsed ChatText and reject unresolved source placeholders. They do not fall back to an unqualified Dialogue. The production boot binds the loaded catalogue digest to the bundle, and the voice cycle retains the exact runtime movement context. It schedules perceived NPCs only, caps the window at 256 thinks, processes 64 per critical section, coalesces late ticks and uses exact actor/sequence occurrences. NPC speech preserves source case and uses the chat owner. A replaced actor has a different placement identity because the digest includes scope and actor generations; the scheduler does not silently reuse an old generation's state.
- Travel hold start validates the frozen command/session, typed Channel World, positive lease, owner generation and work stamp. Ambiguity raises an alert but does not release the hold. A known fee commit merely enters placement pending. Actual arrival re-reads the current capture, alive state and owner; after relocation it records the exact placed result before attempting consume. Retried consume retains that placed record, so it cannot relocate again. Death cancels the invocation before the durable death owner resolves the pending arrival. The top-level newhaven_talk gate handles an existing hold before it can reach paid_travel_talk, refuting concern that a new paid request overwrites an unresolved hold.
- Vocation dialogue clears a prior choice on Monk/no, requires a quoted selection for yes and retains one occurrence/request through retries. Pure confirmation does not change a build. Actual conversion requires level at least eight, no previous vocation, current Character revision and settled training/vitals; it checks current NPC owner and pending/dead spell state, retains the exact request, and after durable commit checks session/scope/build facts again before updating live state. This review does not extend to every build persistence branch.

## Hypotheses resolved

1. Generic bank confirmation constructor does not bypass caps in production: the dispatch wrapper calls valid_amount before storing it; context and fence are revalidated on yes.
2. Missing current item/trigger checks in the pure walking proposal are supplied by the actual scope-transaction/current-map owner and final synchronous Movement CAS.
3. Catalogue/model equality alone is insufficient for a running NPC profile, but production boot compares the complete catalogue digest to the bundle and the cycle binds the runtime context.
4. Fresh TravelHoldSlot creation in paid travel does not establish replacement of an unresolved invocation: the actual parent talk entry checks/reconciles the existing hold first and returns.
5. A reused placement key would strand old voice state; actual ExactActorRef placement identity includes World, typed local scope, scope generation, actor slot and actor generation, refuting that premise.
