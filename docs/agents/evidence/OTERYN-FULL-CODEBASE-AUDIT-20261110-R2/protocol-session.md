## oteryn-identity — REVIEWED

Entrypoints: `PkceMaterial::from_entropy`, `IdentityFlow::await_callback`, `LoopbackRedirect::bind/await_code`. The 32–96 byte entropy bounds produce a 43–128 byte verifier; challenge hashes the encoded verifier, then base64url encodes without padding. Debug/Display redact the verifier and authorization code. Callback parsing bounds the total query and code, rejects malformed percent encodings/UTF-8, duplicate `code`/`state`, empty/control values and compares the received state exactly before exposing the code. Request parsing accepts only a GET callback path and reads with a timeout. The listener binds IPv4 loopback with an OS-selected port, and the normal success/error/token-cancellation path aborts its server task.

Actual callers inspected: `apps/client/src/native_entry/authorize.rs:3-49` uses fresh `secure_random` PKCE bytes and a separate 128-bit random state; `native_entry/challenge.rs:9-58` uses a separate 256-bit state for challenge proof, caps the timeout by challenge remaining lifetime and returns only an owner-validated access token. State is not derived from a timestamp or public identifier. Bounds are applied before callback contents can become usable credentials. An arbitrary first callback can end the local browser flow with refusal, but it cannot pass state binding; this is not evidence of identity bypass. Direct dropping of an `await_code` future would skip its explicit task abort; no concrete production caller dropping that future independently of its cancellation token has been established, so no defect is claimed from this observation.

Existing tests cover PKCE boundaries/redaction, callback decoding/exact state and a real loopback success/mismatch/close sequence. They were inspected, not executed. Package files remaining: none. Live browser/OS and cancellation scheduling qualification: not run.

## oteryn-session-tcp — REVIEWED

Entrypoints: `connect[_with_nodelay]`, `connection::admit[_detailed][_optimized]`, certificate loading. `lib.rs:140-151` configures one explicit trust root, TLS 1.3 and the exact gameplay ALPN; `lib.rs:119-121` rejects an absent or mismatched negotiated ALPN before session admission. `connection.rs:66-81` preserves only typed authenticated refusal/queue values from `Session::admit`, and does not retry an admission on another endpoint. Fallback across resolved addresses happens exclusively during TCP/TLS establishment (`connection.rs:105-127`), before any one-shot grant is written. DNS, TCP and handshake each have bounded waits. Root-file reads are capped at 65537 bytes and reject over-limit files; invalid DER/PEM and multiple certificates fail before use.

The actual client composition `apps/client/src/native_entry.rs:76-185` loads the root before requesting credentials, passes the routed endpoint and TLS name, and preserves refusal queue metadata for the runtime retry policy. No trust-all verifier, TLS downgrade or admission replay fallback was found. Sequential DNS address fallback can consume a separate deadline per address; no production-scale untrusted address-list path or contract violation was demonstrated. Existing tests inspect PEM/DER/bundle rejection, hostname validation and actual Nagle preference on a TLS socket. They were inspected, not run.

Package files remaining: none. Runtime TLS/socket tests: not run. No new finding.

## oteryn-error-codes — REVIEWED

All 12 tracked files (2199 lines) completed. Entrypoints: `error_kinds!`, `Line::render/parse_line`, `emit/init_filter/install_observer`, `Span`, `FlightRecorder`, metric registry, build-source resolution and panic hook. Token sanitation prevents space/control/quote injection; ordered field parsing rejects duplicated or missing required keys and requires code/name/category coherence. Escaped detail is capped at 512 output bytes without splitting UTF-8 or escapes. Reserved extension keys are renamed. Formatted panic payloads are withheld and the default hook is replaced; static payloads follow the documented contract. Nested capture restores its predecessor even across unwind. Ring count, span fields/detail and metric-series cardinality are bounded; metric mutation uses atomics, and registration/export handles lock poisoning. Histogram snapshots are explicitly approximate, not synchronized decisions.

Actual production composition: `apps/game-server/src/node/serve.rs:245-308` installs a non-recursive bounded observer, initializes the filter before first diagnostic use, and returns a failure on a malformed environment specification. `node/scheduler_diagnostics.rs:10-15` uses the span API. Metric callers found use fixed names and bounded label classes. Hypotheses of first-use filter freezing in the server boot path or recursive observer emission were refuted by the actual ordering/body. The public APIs permit callers to provide arbitrary-length raw detail or repeat extension names, but no demonstrated production path violating their call contract was established; this is not a confirmed vulnerability or P1.
