## Outcome

VIP-0 decides the VIP list at Tibia Global parity (owner direction, 2026-09-30).

- **Store:** one list per (Account, World) (ruling R1), shared by the Account's characters on that
  World; entries keyed by CharacterId with a list-local `entry_no`; description, icon, notify;
  three fixed groups and up to five custom groups; a SECURITY DEFINER write function per operation
  under the composition rule 2 fence, with no `CharacterRevision` advance (rule 1 amendment).
  Every command writes a CommandRef receipt (binding digest and outcome) in its own transaction;
  replay first asserts the current recovery fence (mandatory), then returns the stored outcome;
  only the live session, lease and runtime checks, locks, caps and rate checks are skipped on
  replay (§4).
- **Caps:** 20 free, 100 Premium; 5 custom groups with Premium. The Premium caps apply to all
  until the PREM-1 switch-over (ruling R2, applying H2a); over the cap nothing is deleted.
- **Add by name:** World-scoped `name_key` lookup; one `UNKNOWN_NAME` answer for a missing name,
  another World's name or a deleted character; no Account linkage is ever read into a reply.
- **Consent:** an add sends a VIP invitation; status only after the target accepts, only to the
  inviting character (owner answer V2); accept, reject, revoke, a 7-day expiry, 20 pending invitations
  per target; a `vip_status` "hide my status" setting on the social settings row.
- **Presence:** online or offline on this World only (session rows in state 1 or 2), never the
  channel; sealed hints on the CHAT-0 World relay, a node watcher index, and a 60 s reconcile
  without announcements; notify-on-login messages from real transitions only.
- **Wire:** capability `VIP_V1`, one command and one domain, numbers reserved on #162 at
  allocation; offered to clients only when VIP-2 lands.
- **Limits:** one rate bucket per list (20, one per 3 s); rows `VIP0-RL-01` to `VIP0-RL-12`.
- **Owner question V1** (answered c plus a hide option): no status without the watched
  character's consent; VIP-1 and VIP-2 unblocked (ruling R3).
- **Owner question V2** (answered 2026-09-30): one acceptance covers only the inviting
  character, not the rest of the watcher's Account.

No code, migration or content change is made.
