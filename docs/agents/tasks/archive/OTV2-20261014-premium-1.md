## Result

- One Premium fence. The PREM-1 consumer (`premium/mod.rs`, `durability/premium_fence.rs`,
  migration 0029) is the only Premium read of Game. The spell candidate fence is retired and
  deleted: its adapter and mTLS pull (`gameplay_transport/spell_entitlements.rs`), its durable
  consumer (`durability/spell_entitlements.rs`), its ABI (`durability/spell_premium_abi.rs`) and
  its transport-only pull `native_admission_source::read_premium_snapshot`, which had no caller.
- `domain::premium::PremiumGate`: the one value a Premium-gated decision reads. It is closed by
  `Default` and `PremiumGate::CLOSED`. Only a fence read opens it (`pub(crate) from_fence_read`),
  from `PremiumConsumer::premium_current`, which is true only for `CurrentAuthority`. `require()` refuses with
  `PremiumRefusal::NotCurrent`.
- `PremiumConsumer::current_premium`: the same classification under one lock, plus the authority
  revision and the benefit end, `min(effective_until, authority_valid_until, refresh_after)`.
- `SpellPremiumCoordinator` holds the consumer and the registered trusted clock owner. `serve.rs`
  builds it, and the node's `PremiumRefresher` pulls into its consumer, so spells and every gate
  read the fence that admission pulls, fences and proves. A spell view reads the consumer live at
  every use: a failed pull, a revocation, a release, a lapsed lease or a lost clock closes views
  already issued. The projection is current authority only, valid in the owner's monotonic domain
  until the benefit ends, measured from the upper bound of the trusted window.
- Gate API for MAGIC-CAST-1 §4.6, PROG-ADV, HOUSE and GUILD: `ComposedFreshAdmission::premium_gate(account)`
  and `::session_premium_gate(session)`. The second resolves the account the session was
  admitted for from the node's Premium registrations.
- Chat yell: `chat_speak` reads `session_premium_gate` into `YellGate.premium_current`
  (previously hard `false`).
- Fail closed: an unknown account, any class but current authority, no trusted clock owner, a
  lost clock, a failed pull and a restart all read Free.
- Trusted clock (Codex P1, PREMIUM-ACTIVATION-0 §1.1): production registers
  `SystemTrustedClock`, the kernel's NTP-disciplined clock and its `maxerror`, read with one
  read-only `adjtimex(2)` call in the new crate `crates/ntp-clock` (owner decision 2026-10-14,
  option b: isolated FFI; that crate alone denies instead of forbidding `unsafe_code`, with one
  local allow; the workspace lint stays `forbid`). `premium/clock.rs` applies the 5 s bound.
  `TIME_ERROR`, `STA_UNSYNC`, a failed call and a non-Linux target read `None`: Premium closed.
  Codex P1 on f5fd5ff (clock rollback): the process keeps the highest bounds it has read; a
  later reading's upper bound is raised to the highest one read, so a backward step never makes
  Premium current again after a passed cutoff, and a reading wholly before an earlier lower bound
  reads `None` (control plane f5c1777a). Codex P1 on f5c1777a (check apart from update): the
  check and the update run under one lock. A restart resets the high water and reads Free until
  the next proven pull. Codex P1 on 22e73a6 (restart reset): classification also reads
  `AuthorityUnavailable` when the trusted window lies wholly before the evidence's
  `authority_issued_at` (true time is never before it), so a clock set back, also across a
  restart, cannot keep or re-grant Premium past its cutoff once re-proven evidence is newer
  than the clock.
- Activation latch (Codex P1, §1.2-§1.3): migration 0085 `game_premium_activation_latch`, one
  immutable row, runtime `SELECT, INSERT` only. `durability/premium_activation_latch.rs` reads
  it under the shared advisory lock and latches under the exclusive lock (5 s lock timeout).
  `SpellPremiumCoordinator::with_premium_gate` decides `PremiumStatus {NotActivated(PreDelivery),
  Current, NotCurrent}` once per command: `NotActivated` is given only inside the shared-lock
  transaction that read an empty table, with that transaction for the pre-delivery bypass. A
  held latch of another activation, no clock, or a window not wholly after `S` is `NotCurrent`.
  Production composition configures no activation, so Premium is never delivered and every
  account reads Free with no latch write.
- `with_premium_batch_gate(accounts, op)` (GUILD daily job, HOUSE settlement, §1.2): delivery
  is decided once under one shared latch lock and `op` runs once with one status per account,
  in order; `NotActivated` goes to every account inside the gate's transaction. The single and
  batch gates share one settle step.
- The workspace manifest change moves the World bundle compiler's `inputs_digest`; only the
  pin's `inputs_digest` is refreshed (as in OTV2-20261014-rustls-0-23-46).
- Wheel spell admission with `NotActivated` is MAGIC-CAST-1's (control-plane decision).
- `PreDelivery<'g>` borrows an `EmptyLatchHeld` witness that only the latch read makes, after
  the shared lock read an empty table; no other module can build a `NotActivated` status.
- Chat reads the Premium gate only for a yell; say and whisper open no latch transaction.
- The gate commits what a pre-delivery operation left in its transaction; an operation that can
  reject after a write uses a savepoint (`tx.begin()`) and commits it only on success
  (documented on the gate and on `PreDeliveryBypass`; no consumer writes yet).
- `read_premium_activation_with` is the gate's own entry: an architecture-check rule fails the
  workspace check when any game-server file other than its definition, the coordinator and the
  latch's PostgreSQL cases names it (control-plane decision on the Codex P1).
- High-risk authority/persistence qualification: one new durable table (write-once latch),
  migration 0085; gates only narrow (fail closed), never grant. No wire change.
