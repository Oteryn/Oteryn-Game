## Outcome

- 0024: `game_character_account_projections` (per-account `projection_revision`), the outbox
  `game_character_account_projection_outbox` (account, epoch, revision, `created_at` = writing transaction start) and
  the single `game_character_account_projection_epoch`. A SECURITY DEFINER trigger on `game_character_roots` advances
  the revision and queues the change in the Character write's own transaction for every writer: insert, a change of
  owner (both accounts), world, lifecycle or name, and deletion (today only the insert occurs; roots are immutable).
  Existing Characters are queued once at migration time. Operator-only
  `game_character_account_projection_resync(raise_epoch)` queues every account; with a raise the epoch becomes
  `max(current + 1, now in Unix seconds)` (U-LC2 assumption). Guards: epoch only rises, revision only +1, no
  truncation. Runtime role: SELECT on the three tables and DELETE on the outbox only; no CHECK calls a function.
- Publisher (`native_admission_source::account_characters`): exact §4 snapshot/watermark wire, §2.1 name rule
  (printable ASCII subset without `"`/`\`), 64-entry and 16384/512/256-byte bounds, compiled paths, own
  purpose-bound identity (public key distinct from every other purpose), sequential publication on its own capacity,
  outbox cleared on `accepted`/`superseded` for rows of that or an earlier epoch up to the sent revision, watermark
  `complete_through` below the oldest undelivered row and `max_transaction` (3 s) behind the database clock.
  Logs carry operation, result class and timing only.
- Availability: lifecycle 1 is `AVAILABLE`; no other lifecycle exists yet, and an unknown one is omitted (less
  disclosure).
