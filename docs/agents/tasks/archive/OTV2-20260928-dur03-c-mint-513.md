## Outcome

The one-item Ground MINT (VSL-COMBAT-01 §24.3 row C, DUR-03 §§39.1-39.3) is a durable, idempotent
PostgreSQL transaction. Migration 0010 adds the ItemInstance, its one Ground location, the immutable
MINT cause receipt and the event type 2 audit outbox, committed atomically, plus the durable
reservation of each logical MINT transaction (keyed by the full cause tuple) that holds its identities,
fence and DUR03-RL-08 budget across re-freezes, restarts and concurrent holders.
`item_mint.rs` provides freeze, commit, reconcile and read. `item_mint_audit.rs` builds and checks the
registered event type 2 envelope and payload. TRANSFER stays closed.

  refused, never re-reserved.
- `DERIVED`: MINT work units are the participant plus one Ground effect (2 ≤ 3), as in the B4 example.

## Acceptance criteria

- [x] Migration 0010: instance, Ground location, full-cause receipt and item audit outbox, with a deferred
  atomicity guard. The receipt is immutable, with no expiry, deletion or truncate path.
- [x] A duplicate cause returns the identical terminal result, including from a re-frozen candidate and
  after a restart. The same cause with a different intent conflicts.
- [x] Repair round 1: the logical transaction is a durable reservation keyed by the full cause tuple
  (IDs, event bytes, fence, `work_units_used`). A re-freeze, or a re-freeze after a simulated process
  restart, resumes the same IDs and budget. Concurrent freezers and passes share one row and never
  exceed 3 units. After a generation change the reservation is refused and never re-reserved. The row
  has no expiry, delete or truncate path, and the deferred guard requires every MINT to be its
  cause's reserved transaction.
- [x] D52: a MINT whose generation ended (a moved scope or an ended incarnation) is refused and never minted.
  A committed MINT stays committed.
- [x] An ambiguous commit is resolved through reconcile, for both the server-aborted and the
  server-committed case, and the same TransactionId is kept.
- [x] Every registered DUR03 maximum is enforced with max/max+1. RL-08 accepts 3 units per logical
  transaction and rejects the 4th, across re-freezes, a process restart and concurrent holders.
- [x] RL-08 reconciliation work is measured on real PostgreSQL, and re-measured per pass after repair
  round 1 (see the evidence).
