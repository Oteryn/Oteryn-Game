## Outcome

Confirmed against main@39f77b53: CHAT-WIRE-1 already delivered the dispatch (`gameplay_transport/chat_intent.rs`), domain 12, the connection arm and the capability 7 offer, and CHAT-1b-2a the egress queue. The one open item was the resource row `CHAT0-RL-11` (64 lines), which CHAT-1b-2a excluded. It is now registered, and a test in `chat/tests.rs` binds the registry value to `EGRESS_MAX_LINES`. Review rounds (Codex P1/P2): the bound is `queued + in flight`. The connection takes one line at a time (`ChatEgress::next_for_write`, via `chat_next`) and the line stays counted until the connection calls `delivered` after writing it, so a stalled write can no longer leave 64 in flight plus 64 queued. The in-flight line is never retracted; the drop order covers the queued lines. A marker keeps covering overflow until a real line is delivered. Each chat refresh writes at most `EGRESS_MAX_LINES` lines and then returns to the selector.
