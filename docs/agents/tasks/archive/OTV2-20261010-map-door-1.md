## Outcome

Closed and open doors of the bundle map change state by USE (USE-WIRE-V1, command type 2 with a
map target). State is server-authoritative, per channel, scope-ephemeral (a restart starts every
door closed). Walkability, the unified facts, the object revision and the domain 17 map view all
read the same door state, so every session sees the change in its next map delta.

## Architecture and source of truth

- Door pairs: 173 closed/open id pairs (closed C, open C+1) from the Canary item table, checked
  by a unit test against `imports/canary/items-xml/items.xml`.
- Locked doors and closed ids with no consecutive open id stay sealed (blocking, not usable).
- A pair door whose open item is not served by the item index also stays sealed.
- Closing is refused while a live actor (player, creature, NPC, reserved companion) stands on
  the door tile.
- Serve boot refuses readiness with `NoDoors` when a bundle holds no door.

## High-risk authority/recovery qualification

`NOT_APPLICABLE`: door state is non-durable and grants no authority.

## Implementation / findings

Review round 1 (Codex, P1 4238971352, P1 4238971357, P2 4238971359), all accepted and fixed:
- a pair is usable only when the generation's Item profile states the open item as non-solid and
  non-projectile-blocking; otherwise it stays sealed. The active profile has no record for
  1629/1630, so a preprod node now refuses readiness (`NoDoors`) until qualified door facts exist.
- the close check counts players, creatures and placed NPCs (`visible_entities`).
- dropped teleports are excluded before door registration (P2 fixed in place, no follow-up).

Review round 2 (Codex, P1 4239177726, P1 4239177729), both accepted and fixed:
- a domain 17 update composes from `BundleFacts::pinned()`, one read of every door's state, so a
  door's appearance and its object revision always come from the same state even when a `USE`
  commits while the update is composed after the runtime lock is released.
- the close check asks the carrier's own collision census (`position_occupied_by_other`), which
  also counts a companion reserved for an unresolved durable COMMIT and a pending relocation's
  destination; an unreadable position fails closed (occupied), as movement does.

New `map/door.rs` (DoorBook), door-aware `BundleFacts`, boot refusal `NoDoors`, and
`gameplay_transport/map_door.rs` with the USE handler wired in `use_object`.

Review round 3 (Codex, P1 4242611545, 4242611550, 4242611551), all accepted and fixed in one push:
- `use_bundle_door` takes the command's GameSession id and, under the runtime lock and before
  admission, requires the current binding with no control loss; a stale session is rejected.
- Dispositions 7-10 (capability 15) are mapped to the pre-existing negotiated ones for sessions
  without capability 15 (`negotiated_use_disposition`); a test covers the mapping.
- Owner decision D1019 (2026-10-11): WORLD-INTERACTION-0 is ACCEPTED. Only its status line changed.
  No lock entry: the decision is not a cross-repository wire contract (`cross_repository_coordination_id: none`).
