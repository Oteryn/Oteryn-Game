## Outcome

Closed and open doors of the bundle map change state by USE (USE-WIRE-V1, command type 2 with a
map target). State is server-authoritative, per channel, scope-ephemeral (a restart starts every
door closed). Walkability, the unified facts, the object revision and the domain 17 map view all
read the same door state, so every session sees the change in its next map delta.

## Architecture and source of truth

- Door pairs: 173 closed/open id pairs (closed C, open C+1) from the Canary item table, checked
  by a unit test against `imports/canary/items-xml/items.xml`.
- Locked doors and closed ids with no consecutive open id stay sealed (blocking, not usable).
- A pair door whose open item is not served by the item index also stays sealed.
- Closing is refused while a player stands on the door tile.
- Serve boot refuses readiness with `NoDoors` when a bundle holds no door.

## High-risk authority/recovery qualification

`NOT_APPLICABLE`: door state is non-durable and grants no authority.
