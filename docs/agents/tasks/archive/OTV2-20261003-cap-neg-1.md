## Outcome

- `gameplay_transport::capabilities`: `PRODUCTION_OFFERED_CAPABILITIES` (the registry's
  `offered: true` entries with their `requires`; empty on `main`, so production selects nothing);
  `SelectedCapabilities` (bounded, ascending, `Copy`) with `select` (offered ∩ supported, closed
  over `requires`, unknown IDs ignored), `resumable_with` (keep exactly, never widen),
  `command_selected` and `domain_selected` over the registry's capability-owned command types and
  state domains.
- `connection.rs`: fresh admission selects from the authority's offered set (production default;
  tests inject one), echoes it in `ServerAccepted` and keeps it in the session's
  `SessionContinuity`; capability 8 starts domain 13 at revision 0. A resume echoes the original
  selection in `ServerResumeAccepted` and never acknowledges one whose supported set lacks a
  selected capability. Dispatch refuses a command type whose capability is not selected; domain 13
  is sent only with capability 8 selected.
- `resume.rs`: the composed resume refuses, before any durable step, a supported set lacking a
  selected capability (resume-unavailable; the client falls back to fresh admission), and fences
  domain 13 only when it is selected. The resumed session carries the lost session's continuity,
  selection included, unchanged.
- No capability is offered; no migration; no wire, registry or contract change.
