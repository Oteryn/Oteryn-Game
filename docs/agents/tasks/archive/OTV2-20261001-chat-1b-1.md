## Outcome

CHAT-1b-1 registers the CHAT-0 §7 wire. The control plane leased the numbers to CHAT-1 (#162 STATE) and approved the split into this contract and the CHAT-1b-2 runtime (5923553579 and its answer).

- **Capability 7 `CHAT_V1`** (`offered: false` until CHAT-1b-2), **command type 13 `CHAT_INTENT`** and **state domain 12 `CHAT`**: snapshot type 1 is the open-room set, delta type 1 is one line, and delta type 2 is the room set. Registry entries and `chat_v1.proto`.
- **`ChatIntentV1`:** a oneof of `say {mode, text}`, `private_message {recipient_name, text}`, `room {room, text}`, `open_room` and `close_room`; an empty or doubled oneof is refused. The whole CHAT-0 intent is defined now, so CHAT-2 needs no new capability.
- **`ChatIntentResultV1`:** the §7 results plus `REJECTED`. `wait_seconds` is `1..=1280` with `MUTED` and `EXHAUSTED` only (5 s × 16², `CHAT0-RL-04`).
- **`ChatLineV1`:** kinds `LOCAL`, `PRIVATE`, `ROOM` and `DROPPED` (the `CHAT0-RL-11` marker). Each field is allowed only on its kind.
- **Bounds:** intent 1,148 bytes, line 1,194, result 8, room set 4. Text is at most 1,020 bytes (`CHAT0-RL-01`) and a name at most 120 bytes (the CHAT-0 §5 relay bound).
- **Resource limits:** rows `CHAT0-RL-01` and `CHAT0-RL-07` in `RESOURCE_LIMITS_REGISTRY.json`. `CHAT0-RL-11` has a server-side consumer, so CHAT-1b-2 registers it.
- **Codec:** `crates/protocol-oteryn/src/chat.rs`, strict in both directions, with a test that binds the registries and the proto to the codec constants.

## Decisions for protocol review

- **A local line carries the speaker's name as well as its spatial identity.** CHAT-0 §7 says "speaker actor or name". The client needs the name to show "Name says:", and the spatial entities carry no name. A player's name is not a restricted identity under FND-02 §10, because rooms send it anyway. The alternative is a name lookup in another domain, which does not exist.
- **The open-room set is a 4-bit mask.** A repeated enum would need packed encoding, which the strict subset refuses.
- **The whispered "pspsps" goes as the line's text,** in Canary form. The client does not need its own rule for it.
