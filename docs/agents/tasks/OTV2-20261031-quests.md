## Authority and recovery qualification

All eleven Grizzly action families use the existing Character revision slot and
current generation fence. Rules read the locked state; historical receipts are
checked before applying another effect. Task-run revision observed at death prevents
a delayed kill from advancing a later run. Party identity/revision is independently
verified by the native World owner; contention is retryable, not an immutable refusal.
Presence metadata alone does not invalidate an unchanged party roster.

Boss storage1->2 and the visit are one quest transaction. The database clock provides
the exact600-second deadline. Room expiry preserves RETURN_PENDING for an offline
character. Return acknowledgment persists LastPosition and CLOSED in the same
transaction. A pre-COMMIT retry record survives an expiry whose SQL reply is lost;
reconciliation reads the exact original visit before acting. No timer creates kill
credit, XP or loot when administratively removing monsters.

A multi-action NPC utterance retains its original cause and action batch across an
unknown outcome. Definitive partial refusal refreshes committed quest tracks and
requests existing XP obligations before another utterance, preventing a stale-cache
loop. A full backpack leaves the Demon holy-icon entitlement pending; a later accepted
Grizzly interaction uses the original existing MINT authority to deliver it once.

Filled chests freeze a complete ordered child plan with stable identities. Root,
children, nested custody, key attributes, authored text, one-item audit events and
shared completion claim commit together. Unknown Item semantics refuse the complete reward. Capacity
and weight checks run before reserving a fresh claim.
