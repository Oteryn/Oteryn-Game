## Conventions used here

- **Client entry rule.** Link 1 counts only when a non-test call chain starts in `apps/client/src/bevy_shell`.
  - That chain runs through the portable play layer `apps/client/src/features/*` and `apps/client/src/play/*`, which is mounted by `build_support/play_features.rs` and is not windows-gated.
  - It then reaches `crates/client-ui` or `crates/client-runtime` and the session crate `crates/session` (`session.gated_command`).
  - If a feature is reached only from `apps/client/src/windows_shell/input.rs` (`*_input`) or from `#[cfg(any(windows,test))]` code, it is marked **SERVER-ONLY**, even when client-ui has request and reducer code for it.
- **Client reducer.** This is the client-ui `apply_result`, or the session decoder of a push, as reached through `apps/client/src/play/session_loop.rs` or the play feature `protocol.rs` event handler.
- **Server-pushed rows** need links 2-4 only; they say "push" in the note.
- **"no dedicated wire"** marks a row whose behaviour is server-internal and reaches the client through a generic carrier: spatial snapshot, presentation, use (cmd 2), NPC talk (cmd 7) or container view. Such a row is BOTH-WIRED when that generic chain is wired.
- **"Partial:" in a note** means the main path is wired but some sub-commands have no Bevy entry. The missing sub-commands are listed under Client gaps.
