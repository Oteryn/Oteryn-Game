## Production paths

I04 uses the base's MAIL WriteText command and fenced write-once producer.
Ctrl+Alt+M now opens the native writing/mail panel with the selected inventory
item prefilled. UTF-8 text and item-specific limits stay on the existing wire.
Successful text save, exhaustion and refused rewrite have distinct feedback.
The same command's receipt resolves before transformed/retired handles.
Thirty-eight already qualified writing/fixed-target profiles gain source-bound
physical admission; pending text qualifications are not promoted.

I05 retains the base's stage-indexed timer, immutable chains and revision-indexed
custody handoff. It introduces no second timer. Ground and active/reconnectable
Character main/nested/equipment execute due stages. Other storage retains the
same pending schedule until withdrawal; this is the base behavior recorded in
GAP-SV2, not a claim that an inactive storage owner eagerly mutates every item.
Frozen charge/duration rows now follow real custody moves. The old generic
movement guard rejected every initialized timed row; migration 0980 captures
that row itself and permits only unchanged, positive, non-lit budgets or spent
rows. A deferred same-transaction proof rejects creation, deletion or modification
of the timed row during movement. Deadline/lit items stay outside this grant.

The qualification here closes the ledger's stated storage/chains gap for admitted
charge, frozen-budget and ordinary-decay cohorts. It is not a claim of complete
timed-item family parity. Continuous torch clocks and their Ground/House hosts
remain the separate, unfinished TIMED-RT-1c/TIMED-HOUSE-1 packets in the accepted
TIMEDITEM0B decision and `docs/agents/tasks/ITEM-TIMED-1.md`; no torch profile or
put-out/deadline writer is promoted by this patch.

I10 adds the native furniture catalogue/panel to existing capability 207,
command 402 and fenced House mutation owner. The read is custody-first and bounded
by the existing 2000 House roots and 20 main-backpack entries, with 8 entries per
page. Private UUID/revision/ACL values are decoded and retained in client state;
the panel shows numbered names and actor placement coordinates. Pending requests
are gated; commit/refusal clears selection. The existing mutation rechecks all
custody, ACL, generation, capacity, occupancy and lineage facts. Full-fluid refusal
is preserved as the accepted base difference, including its existing PostgreSQL
assertions that neither fluid nor transition history changes.
The existing furniture pair 30231 -> 35027 has no target XML name in either
pinned donor. This does not remove its already-owned action: Wrap is labelled
with the known source name, festive table; Unwrap is labelled with the known
counterpart. The catalogue never invents a canonical name for 35027. A real
House-query regression covers this previously hidden entry.

I14 enters through ordinary USE_WITH and the existing consume/transform receipt.
Flask consumption, potion output and dispenser exhaustion share one transaction.
Non-final debits reuse `game_item_timed_states`; final retirement retains the
preceding timed row as the timed expiry owner does. Nested targets use actual
bounded carried ownership. Ground targets require a current, adjacent native
Ground context and a full item/location snapshot recheck under owner locks.
Receipt-bound SQL proofs extend only dispenser checkpoint and exhaustion arms.
A replay, including a reconstructed owner, cannot debit charges or mint again.
Named-House targets use their own current session/node/House fence and exact
placement plus reclaim provenance; they do not substitute a Channel fence.
Exhaustion removes House custody/provenance through a receipt-bound RPC.

All 22 dispenser mappings are admitted. Current mana variants 53162/53163/53164
use the existing potion consumer with Crystal's ranges, level/vocation gates and
large empty-flask return. Demonic blood 6558 uses the existing fenced conversion,
uniform command-bound selection of 236 or 237, committed native presentation,
and Demonic Barkeeper progress. Existing owner-selected Global potion values,
condition potions, special foods and their requirements remain unchanged.
Plain USE and the explicit timed-item Use action cannot spend dispenser charges;
Inspect remains available.

Owner decision, 2026-11-06: no Wiki fetch tonight; follow Crystal's leftover-first,
potion-production, then dispenser-debit/removal order and retain flask conservation.
The writer retains every unfilled flask before minting potions, then checkpoints
or retires the dispenser. I14 is **wiki-pending** for the canonical full-container
overflow fact. This packet does not claim to implement Lua's independent
`player:addItem(..., true)` Ground fallback: an exhausted carried keg can free the
final committed inventory slot, while a full carried parent with a Ground cask
returns NoRoom without changing either input, charges, receipts or item history.
The two cases are verified separately; no conservation assertion is weakened.

The original red keg result (`NothingToUse`) came from missing current native
admission for the target definition. After admission, two additional atomicity
checks rejected legal multi-flask output: source-ordinal reuse required quantity
one, and completion assumed every input debit was one. Migration 0980 adds exact,
recipe-bound proofs for the declared flask count; neither test nor general guards
are relaxed. The fixture now retains actual stream continuity for cached replay,
and separately recreates the owner to prove durable replay.
