The new carrier neighbor entry compares the exact existing snapshot and commits
both axes together; the original cardinal-only entry retains its contract.
Tests reproduce the previous `MovementNonCardinal` refusal before that entry was
added. Jumps, unchanged positions, floor changes and blocked destinations remain
refused. The candidate budget remains one collision lookup.

Client controls use the existing stable physical Numpad 1/3/7/9 mappings from
`crates/input-platform/src/winit_adapter.rs`; the live mailbox and Session both
require negotiated capability 449. Offline/unselected input stays unchanged.
The capability number was checked against main `2033ddc54d` and open PRs:
447/448 belong to #3058, and 449 was the next free capability. No new migration.

`m40_native_diagonal_dance_full_sequence_and_replay` ran on PostgreSQL 18.6:
69.36 seconds in its isolated receipt-enabled process, 69.40 seconds including
the parent. The story starts only the canonical NPC dance prerequisite, then
performs every source step through command 1. It proves all four diagonals,
exact x3 duration receipts, wrong-step reset, no movement without negotiation,
every literal replay and exactly one Talented Dancer achievement.

The initial PG run failed at the positive receipt assertion after 43.40 seconds:
receipts are independently disabled by default by `OTERYN_STEP_WAIT_RECEIPTS`.
The test now isolates that actual rollout flag in a child test process and
requires its full-journey marker, rather than changing global test environment
or removing the duration assertion. It does not arrange fifteen dance stages.
