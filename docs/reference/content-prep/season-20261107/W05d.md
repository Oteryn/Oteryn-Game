## Santa's failed-script prefix and destination order

Crystal `201189f871d23597b82caf88fd611454a2ddefb8` requires LuaJIT in
`cmake/modules/BaseConfig.cmake:21` and lists it in `vcpkg.json:13`.
The source-qualified runtime reference is LuaJIT
`ea9eb7edb5eac4a9d175d74523db34fac0fa5180`, `src/lib_math.c:132-179`:
its one-argument branch at line155 evaluates
`d = lj_vm_floor(d*r1) + 1.0`. Consequently the call with zero in Crystal
`data-global/npc/santa_claus.lua:97` returns1 and indexes an empty table,
producing nil. Santa creates bag6510 at line111 before `#reward` fails at
line114. This prefix leaves an empty bag, does not set storage840293 at
line122, and does not reach the normal NPC reply. A retry with a new command
may create another bag; replay of the same command must reuse its receipt.
The immutable reference file SHA-256 is
`cd0f568d16d1a36f82b7aa6ced300da290336e891d01df6147fd39a784bb8d4d`.

Normal `Player:addItem` insertion first uses managed obtain routing
(`src/game/game.cpp:2782-2805,3454-3500`) and then ordinary carried-container
breadth-first routing (`src/creatures/players/player.cpp:4932-5037`), followed
by the source Ground fallback. Exact bag6510 has no special equipment slot:
`data/items/items.xml:17977-17980` supplies capacity5/weight600 only;
`src/items/items.hpp:324` defaults to `SLOTP_HAND`, whose generic bag insert
is rejected by `src/creatures/players/player.cpp:4659-4661,4734-4738`.
`config.lua.dist:344` disables putting arbitrary items in the ammo slot.

The bag is inserted before its contents. Each child addition independently
calls the existing owner capacity check: `src/items/containers/container.cpp:558-563`
forwards to `src/creatures/players/player.cpp:4597-4605`.
`src/lua/functions/items/container_functions.cpp:156-202` returns failure
for a refused child, which Santa's loop at lines112-119 ignores. A heavy
refused child must therefore preserve already inserted children and allow a

not charge the player's carried capacity. These are requirements for the
