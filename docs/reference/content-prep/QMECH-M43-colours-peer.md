# M43: selected peer quest-state predicate

The accepted chosen recipe is `content/quests/definitions/quests-00300-00351.json#/records/38/definition/recipe/stages/2`: pair remaining blue powder with a yellow-marked participant, then report the green pairing to Nathaniel. This change supplies that server-side peer predicate and actor-only s3 advancement. It does not invent a new event vote, calendar or team-selection system.

Checked source: <https://raw.githubusercontent.com/opentibiabr/canary/47dfd51f/data/items/items.xml> was fetched on 2026-11-08. Item12204 is "envelope from the wizards";12208 and12228 are both "strange blue powder". The retained opening owner uses12228 for the remaining powder. Walkthrough locator: <https://tibia.fandom.com/index.php?curid=50860&oldid=1128664>.

Chosen mapping retained from the opening contract: no mark=0, blue=1, yellow=2, green=3. A blue actor at stage2 consumes its exact selected12228 instance only after a different, adjacent, live player's fresh durable colour equals2. Only the actor advances to stage3/green. The peer is read-only. Self, stale ingress/session/lease/revision/scope, a different definition pin, or a busy peer refuses before charging.

Package boundary: the tested envelope/mark-blue opening and its native Item provider remain in frozen PR #3042 (`claude/happy-davinci-ijz3wy-wpkg2`). This delta does not copy that PR. `reward_callbacks::colours_peer` attaches the new callback only when that exact opening owner is present; otherwise it remains authored data and cannot expose a partial route. The generic `peer_requires` field is independently available to other carried callbacks. This is an M43 mechanic/step claim, not a whole Colours completion claim.

Durable arrival gap: a free NPC teleport can commit an arrival before runtime placement catches up, leaving the prior peer entity visible. Peer predicates now reject a pending arrival while retaining the peer root lock, before the actor input-consumption path. The real PG regression `m43_peer_postgres_rejects_pending_arrival_before_reward` failed on this boundary (4.31s) and passed after the guard (3.897543869s); ordinary yellow eligibility and eligibility after arrival consumption still pass without peer-state or actor-revision writes. This uses existing tables and no migration.
