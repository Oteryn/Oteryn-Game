This generated supplement covers all **20,640 attack/defense slots from 5,188 donor profiles** in the accepted r22 normalized import. It is not a claim that 5,188 monsters or 20,640 attacks execute in Game. The native r24 population remains a separate 1,508-profile candidate.

`monster-slot-presentation.jsonl.gz` contains one row per source slot. Each row retains its source candidate/group/index, raw parameters, actual `readSpell` setter variants, separately retained semantic sound defaults, registered Combat variants and conditions, registered Spell sounds, source hashes and explicit runtime status. These rows supplement converted authoring bundles; they do not allocate native IDs, activate abilities or redistribute sound/media binaries.

## Concrete sound omission repaired

The previous slot import omitted automatic sounds generated by the donor registration helper. Both pinned helpers select casting/impact sounds from projectile type, attack element, shape/radius, drunkenness duration and target distance. Melee selects randomly between three close or two ranged sounds. The new supplement preserves every possible selected sound instead of arbitrarily fixing one random result.

Both helpers contain a source defect: their default impact branch invokes `castSound(sounds.impact)` instead of `impactSound`. The source capture preserves the actual final setter behavior **and** the intended default cast/impact pair as distinct fields. We do not silently “correct” donor behavior or pretend those settings are native playback. Donor sound IDs are resolved against the exact pinned `SoundEffect_t` header; **native sound asset bindings and client playback are still unverified**.

Eleven source slots retain invalid/unbound visuals: `CONST_ME_REDSPARK`, `CONST_ME_POISON`, numeric `248`, or `CONST_ME_CONST_ME_HOLYAREA`. No guessed replacements are admitted. Registered custom callbacks without captured Combat remain explicitly unresolved; no engine or encounter interpreter is fabricated.

## Reproduction and checks

Install the scoped pinned dependency into your existing development environment; no machine-specific Python path is required:

```sh
python -m pip install -r tools/content-schema/monster-authoring/requirements-presentation.txt
SPELL_SOURCE_ROOT=/workspace/spell-sources python -m unittest discover -s tools/content-schema/monster-authoring -p test_monster_presentation_closure.py -v
python tools/content-schema/monster-authoring/build_monster_presentation_closure.py \
  --import-root /workspace/spells-r22-monster-import \
  --canary /workspace/spell-sources/canary --crystal /workspace/spell-sources/crystal \
  --output /tmp/monster-presentation-new
```

The output directory must not already exist. Reproduction verifies exact helper/header Git blobs and every referenced monster/registered-script hash. Sparse checkouts may use the hash-verified approved import `source-inputs` fallback. Eleven focused tests pass, including both pinned donors, random sound alternatives, area-default visuals, poison tick/duration settings, and positive/negative registered Spell lookup. Registered lookup is essential: an unknown spell uses condition damage setters, while a registered attack uses Combat damage setters. The test prevents inventing conditions by treating all Spell lookups as absent.

Sources were read locally through ordinary Git/HTTP snapshots, not Remote Desktop. Fresh wiki access and gameplay comparisons are recorded by the separate source-research lane. This source supplement claims no fresh wiki verification.

The recording Lua environment denies filesystem/process/module access and Python builtins, caps memory at 16 MiB per donor, and bounds helper execution at one million instructions with JIT disabled.
