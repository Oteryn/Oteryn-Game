## Explicit gaps

The requested earlier donor revisions are Crystal
`ff7ede593c69d4c658b382c97443e8155926924a` and Canary
`99902524e052f37574194466c2949c576e4ab269`. On 2026-11-05, complete,
non-truncated Git tree queries for both revisions contained no `echo_warden`
paths. Crystal's requested library and loot callback URLs return HTTP 404.
The in-repo source inventory agrees: the earlier Crystal spell capture has
Death Echo, not this encounter. The existing production owner therefore
continues to use the later donor already cited by its rules.

The audit lists 8 normal / 4 influenced / 4 plus Warden outcome families,
but the available Echo donor implements only guaranteed Warden plus 7–12
minions. It specifies no selection among the three current families and
no catalyst/dust payouts. No odds, payout amounts or influenced profile
are invented. Those current-family/reward differences remain explicit gaps;
SV16 is a partial slice, not a claim of complete current-rule parity.

## Implementation boundary

Extend the existing channel owner's portal execution. Keep new expiry
state and logic in its own module with one-line state/routing registrations.
Only physically created raid children receive deadlines; natural monsters
enlisted by the aura do not. Remove exact live actor incarnations through
the existing encounter owner, without synthesizing a death. Dead actors
remain subject to the existing pending corpse/kill settlement cleanup.
No migration, mechanic ID, generated content or pin change is needed.
