# Native spell source-world candidate

This local candidate adds `native-source-spell-world-qualification-3`. It preserves the accepted entry qualification and its four-cell `OTSCENG1` carrier. The separate map carrier admits at most 4,096 source cells, a 32×32 rectangle and four captured floors. Activation requires an explicit `source_world` manifest pin and a newly matching control-plane issuance for both outer artifacts and the source-qualified frame. Possession of the source document or a matching stored scope does not authorize activation, movement or a cast.

The pinned Canary revision is `99902524e052f37574194466c2949c576e4ab269`. The actual tracked `data-canary/world/canary.otbm` contains Thalom town 6 and Temple `(5854,5298,5)`. The candidate captures genuine positions `x=5840..5871`, `y=5283..5314`, source floors `5..8`: 2,833 actual tiles. Native coordinates are `x=source_x-5854`, `y=source_y-5298`, `floor=-source_z`. This preserves east/south/up conventions and the source Levitate floor-7/8 restriction. No missing neighbour or floor is synthesized. The first native entry is `(0,0,-5)`.

`tools/content-schema/native-gameplay/build_source_world.py` verifies the actual source git HEAD, each git blob identity and SHA-256, the OTBM selected-node attribute closure, protobuf item bank and XML overrides. There is no `items.otb` in this source revision. Ground class and speed come from the actual Canary item-loader interpretation of `appearances.dat`, with XML overrides. Tile collision, projectile, immovable path/solid, floor-change and protection-zone facts follow the pinned item/tile/IOMap implementations. Source IDs bind explicitly through `ProjectV2SourceIdentityBinding`; the complete ImportBatch and Source records remain in the server document. The 37 mutable Item aliases carry separately declared actual native Item production targets from the qualified Crystal Item profiles. Canary map provenance and Crystal native binding provenance retain their own pins; the initializer compares the whole active native binding and Canary item flags before admitting a placement. No source number acts as a DefinitionRef.

The qualified map retains immutable source stacks. Its 49 mutable cells contain 57 actual source placements: 35 ordinary pickups, 12 doors, eight beds and two teleports. The static cell index keeps these cells Unknown. Migration0048 adds an independent map-initialization cause to the existing ItemInstance/Ground owner, with exact same-transaction source receipt and private audit, actual current recovery/node/assignment checks and active artifact/frame/map binding. The callable bounded owner pass mints only explicitly qualified native Items, once per World/Channel/content/placement. Current collision consumers verify every required initialization cause and then read the actual ordered Ground rows under the same transaction. Untouched Door collision follows its actual current Item Definition/state revision and qualified flags. Bed/teleport STEP behavior and Door USE remain unavailable until their interaction owners are integrated; a persisted row does not assert those behaviors.

A newer scope generation adopts existing map-source custody through an immutable handoff receipt. It changes only the ownership generation of a compatible existing Ground row. It preserves the original MINT, Item identity/definition/quantity/state, source order and position. Picked-up, moved or retired Items are never recreated from historical initialization evidence. The ordinary admission guard reader validates retained publication history and mirrors before this mutation. Source Item state that lacks current qualified movement flags remains Unknown. Out-of-capture queries also remain Unknown. Missing tiles inside the complete captured rectangle are known static absence; they still require a real transaction-bound item-owner read when used as a Levitate probe. Legacy incompatible placement/revision rows cannot be filtered into a false empty result.

The genuine Rope origin is source `(5861,5312,8)`, native `(7,14,-8)`, ground 386, speed 120. Its actual north landing is source `(5861,5311,7)`, native `(7,13,-7)`, ground 353, speed 140. These are positive source geometry facts, not a claim that a player has reached either cell. The Temple begins on floor 5. For mutable cells, a bounded collector resolves only the cells requested by the unchanged algorithm using fresh current-player Item reads, retains the real SQL owner locks, and binds the final STEP proof to the originating physical transaction. The movement/pacing consumer uses that proof instead of recomputing against static Unknown cells. Source Levitate still forbids moving from source floor7 down to8. A full Rope journey must pass actual current collision and interaction owners; the Rope coordinates alone prove no player journey.

The server envelope `OTNSW03` carries the inner admitted gameplay artifact, the source map document and the digest of its paired client envelope. The client envelope `OTNCW03` carries the original inner client artifact plus native frame/start/cells and immutable native appearance identities. It excludes git hashes, source numeric IDs and server spell flags. Source mutable stacks are explicitly pending owner admission. Server and client bounds are 96 MiB and 8 MiB respectively; the source document itself is limited to 8 MiB. Strict decoding rejects truncation, extra bytes, mismatched section hashes, nested map envelopes and mismatched client geometry.

The original entry Door remains an inner baseline dependency. Its physical placement belongs to its original frame and must never be relabelled or published as a placement in this source map. Spell tile consumers select the source-qualified immutable map owner only after all current World/server/client/frame/map pins agree, then compose the actual durable item overlay under the same physical transaction. No fake empty Door runtime or second actor-position store is created.

The captured source region has no House tiles. It does not allocate a House, custody, membership, owner or Premium entitlement. Aleta and House GUI use the separately fenced World-global ACL owner only after real House placement/custody/interior admission.

The candidate condition owner additionally represents source invisibility, finite spell skill bonuses, source regeneration sub-IDs and exact Item appearance overrides. These effects share the existing actor condition store and its owner clock; skill bonuses do not alter durable base skills or training. Item appearance uses a qualified native Item definition and active artifact pin, rather than interpreting a source item number as an outfit identity.

This candidate does not change the accepted resource registry or claim that the larger carrier is approved for production.
