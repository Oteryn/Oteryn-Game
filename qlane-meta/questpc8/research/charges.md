## Charge semantics and defaults

Crystal `player:addItem` passes the requested count into subtype items (`src/lua/functions/creatures/player/player_functions.cpp:2815-2843`); `container:addItem` passes its count to item creation (`src/lua/functions/items/container_functions.cpp:177-183`). `Item::CreateItem` uses a nonzero explicit item count as `CHARGES`, and uses the item definition's default only when the count is zero (`src/items/item.cpp:335-339`). Thus an explicit raw `1` is one charge, not “use default.” These are pinned Crystal runtime semantics, not proof of intended Tibia reward behavior.

Pinned Canary `data/items/items.xml` defaults: Silver Amulet 3054 = 200 (`:6946-6951`); Bronze Amulet 3056 = 200 (`:6966-6971`); Might Ring 3048 = 20 (`:6878-6894`); Stone Skin Amulet 3081 = 5 (`:7243-7249`); Elven Amulet 3082 = 50 (`:7255-7266`); Garlic Necklace 3083 = 150 (`:7272-7277`); Protection Amulet 3084 = 250 (`:7283-7288`); Dragon Necklace 3085 = 200 (`:7294-7299`); Ice Rapier 3284 = 1 (`:8525-8530`). [Pinned definitions](https://raw.githubusercontent.com/opentibiabr/canary/47dfd51f45280a59a1d3e50ba7edd573d7234446/data/items/items.xml). Defaults are reference data, not Wiki-confirmed reward charges.

## Five explicit one-charge source recipes

Crystal's reward handler calls `player:addItem(params.itemid, params.count)` for direct rewards and `reward:addItem(itemid, count)` for container children (`data-global/scripts/actions/system/quest_reward_common.lua:187-215,232-248`); Canary does the same with `params.count` (`data-otservbr-global/scripts/actions/system/quest_reward_common.lua:59-86,108-124`). Both runtimes pass a nonzero subtype-item count into item creation (Crystal `src/lua/functions/creatures/player/player_functions.cpp:2815-2843`; Canary `src/lua/functions/creatures/player/player_functions.cpp:2365-2402`), and both container APIs pass the count to `Item::CreateItem` (Crystal `src/lua/functions/items/container_functions.cpp:177-183`; Canary `src/lua/functions/items/container_functions.cpp:171-178`). `Item::CreateItem`/`Item::Item` stores a nonzero explicit count as `CHARGES` and uses the item default only when the count is zero (Crystal `src/items/item.cpp:335-339`; Canary `src/items/item.cpp:699-717`). Thus both pinned donor recipes create one charge. Resolve the raw-count/default mismatch in favor of the explicit reward argument; the Wiki supplies no competing numeric charge amount. This is a donor compatibility decision, not a claim that live Tibia uses these recipes.
